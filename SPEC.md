# Завдання: реалізувати Windows-застосунок Google Drive Downloader

Ти Senior .NET Software Engineer з досвідом понад 10 років, спеціалізуєшся на C#, .NET 10, Windows Forms, Google Drive API, OAuth 2.0, роботі з Excel і розробці автономних desktop-застосунків.

**Мета:** реалізувати повноцінний Windows-застосунок для масового завантаження приватних файлів із Google Drive за посиланнями з XLSX, із перейменуванням відповідно до назв, указаних в Excel.

Потрібно створити реальний, працездатний проєкт із вихідним кодом, конфігурацією, тестами, документацією та інструкцією публікації.

Не обмежуйся прикладами, псевдокодом або заготовками.

## 1. Технологічний стек

Використовуй:

- C# 14, .NET 10, Windows Forms.
- Target Framework: `net10.0-windows`.
- Google.Apis.Drive.v3 і Google.Apis.Auth для інтеграції з Google.
- ClosedXML для читання `.xlsx`.
- Microsoft.Extensions.Configuration.Json для конфігурації.
- Microsoft.Extensions.DependencyInjection для DI.
- Serilog і Serilog.Sinks.File для журналювання.
- Windows DPAPI для захищеного зберігання OAuth-токенів.
- `async/await`, `CancellationToken`, `IProgress<T>`.

Застосунок має працювати у Windows 10/11 x64.

Розгортання: Self-Contained, Single File (`win-x64`). Користувач не повинен встановлювати .NET Runtime, Visual Studio, Python, Microsoft Office чи додаткові фреймворки.

Не використовуй WPF, Avalonia, Electron, ASP.NET Core, базу даних або серверну частину.

## 2. Архітектура

Реалізуй один WinForms-проєкт із логічним поділом на шари:

**Presentation:**
- MainForm — головне вікно.
- Відображення прогресу та журналу.
- Обробка дій користувача.

**Application:**
- BatchDownloadService — керування пакетним завантаженням.
- ExcelReader — читання XLSX.
- DriveLinkParser — розбір Google Drive URL.
- FileNameResolver — формування імен файлів.
- DownloadResult — модель результату обробки.
- DownloadProgress — модель прогресу.

**Infrastructure:**
- GoogleAuthService — авторизація.
- GoogleDriveService — робота з Google Drive API.
- FileStorageService — збереження файлів.
- LoggingService — журналювання.

Дотримуйся SOLID, але не створюй зайвих абстракцій або складної багатопроєктної архітектури.

Бізнес-логіка не повинна залежати від WinForms. Використовуй DI та асинхронне виконання, не блокуй UI-потік.

## 4. Google OAuth 2.0

Файли Google Drive не є публічними. Вони можуть належати різним власникам.

Користувач програми має доступ до цих документів через власний Google-акаунт.

**Використовуй OAuth 2.0 Desktop Application, а не Service Account чи API Key.**

Обов'язкові вимоги:

1. OAuth 2.0 Authorization Code Flow із PKCE.
2. Авторизація через системний браузер.
3. Локальний loopback redirect.
4. Scope: `https://www.googleapis.com/auth/drive.readonly`.
5. Підтримка offline access.
6. Автоматичне оновлення Access Token.
7. Повторна авторизація, якщо Refresh Token недійсний.
8. Збереження токенів між запусками програми.
9. Захищене зберігання токенів за допомогою Windows DPAPI у контексті поточного користувача.
10. Кнопка для виходу з Google-акаунта і зміни акаунта.
11. Не використовувати незахищений Google FileDataStore для зберігання токенів.
12. Не записувати Access Token, Refresh Token або Client Secret у логи.

Використовуй офіційну Google API .NET Client Library, зокрема GoogleWebAuthorizationBroker, якщо її актуальна версія підтримує необхідний PKCE flow. Не реалізовуй власну криптографічну OAuth-схему без необхідності.

Не вимагай Google-пароль у самому застосунку.

### 4.1. Передача програми іншому користувачеві

Застосунок передаватиметься іншим користувачам без OAuth credentials розробника.

Потрібно реалізувати незалежну конфігурацію:

- За замовчуванням OAuth Client ID та Client Secret у `appsettings.json` порожні.
- Користувач може записати власні OAuth credentials у конфігурацію.
- Додатково підтримати імпорт стандартного OAuth Desktop JSON-файлу, завантаженого з Google Cloud Console.
- Імпортовану конфігурацію зберігати у `%LOCALAPPDATA%\GoogleDriveDownloader\`, окремо від EXE.
- Перевіряти, що імпортований JSON має тип OAuth Desktop Client, а не Service Account.
- Якщо credentials не налаштовано, показувати інформативне повідомлення з інструкцією.
- Не завершувати програму аварійно через відсутню конфігурацію.
- Локальні токени повинні бути прив'язані до поточної OAuth-конфігурації; після її зміни необхідно виконати повторну авторизацію.
- Програма не повинна залежати від Google Cloud проєкту розробника.

Не вбудовуй реальні Client ID, Client Secret, Service Account JSON або токени у вихідний код чи EXE.

## 5. Google Drive API

Для роботи використовуй Google Drive API v3.

Підтримай такі типи URL:

- `https://drive.google.com/file/d/{id}/view`
- `https://drive.google.com/open?id={id}`
- `https://drive.google.com/uc?id={id}`
- `https://docs.google.com/document/d/{id}/edit`
- `https://docs.google.com/spreadsheets/d/{id}/edit`
- `https://docs.google.com/presentation/d/{id}/edit`

За можливості підтримай інші офіційні форми URL та параметр `resourcekey`.

Не отримуй документи через HTML scraping і не використовуй сторонні сервіси завантаження.

Послідовність:

1. Отримати File ID.
2. Запросити метадані через Google Drive API.
3. Визначити MIME type.
4. Перевірити `capabilities.canDownload`.
5. Вибрати спосіб завантаження.
6. Завантажити або експортувати файл.
7. Перейменувати й зберегти локально.

За потреби враховуй Shared Drives та параметр `supportsAllDrives`.

Якщо користувач не має доступу, документ видалено або завантаження заборонено власником, зафіксуй відповідну помилку. Не намагайся обходити обмеження Google Drive.

Не визначай фактичний тип файлу лише за URL.

## 6. Завантаження та формати документів

Для звичайних файлів (PDF, DOCX, XLSX, ZIP, TXT, зображення та інші) завантажуй оригінальний вміст.

Для Google Workspace:

- Google Docs → DOCX.
- Google Sheets → XLSX.
- Google Slides → PPTX.

Для звичайних файлів використовуй завантаження медіаданих через Google Drive API, а для Google Workspace — експорт у відповідний MIME type.

Врахуй, що стандартний `files.export` має обмеження 10 МБ. Для перевищення обмеження показуй зрозумілу помилку; не видавай частковий файл за успішний. Альтернативний механізм Google Drive `files.download` можна описати в документації як майбутнє розширення, якщо не реалізовано в MVP.

Не завантажуй повністю великі файли в оперативну пам'ять, якщо доступне потокове завантаження.

## 7. Перейменування файлів

Назву файлу потрібно брати зі стовпця «Назва».

Розширення визначати за типом фактично завантаженого або експортованого документа.

Приклад:

Excel:
- Назва: `Звіт за 2025 рік`
- Посилання: Google Drive PDF.

Результат:
- `Звіт за 2025 рік.pdf`

Правила:

1. Не дублювати розширення, якщо воно вже коректно вказане.
2. За необхідності виправляти розширення відповідно до фактичного формату.
3. Замінювати недопустимі Windows-символи.
4. Обробляти зарезервовані імена Windows, кінцеві пробіли та крапки.
5. Не дозволяти path traversal або вихід за межі вибраної директорії.
6. Якщо файл із такою назвою вже існує — додавати `(2)`, `(3)` тощо.
7. Ніколи не перезаписувати наявні файли без окремого явно заданого режиму.
8. Враховувати нечутливість Windows до регістру назв файлів.

Завантажувати файл спочатку у тимчасовий `.part` у вибраній директорії.

Після успішного завершення виконувати безпечне перейменування.

При помилці чи скасуванні видаляти незавершений тимчасовий файл.

## 9. Логування

Використовуй Serilog.

Зберігай логи у:

`%LOCALAPPDATA%\GoogleDriveDownloader\logs\`

Вимоги:

- Щоденна ротація.
- Збереження журналів за останні 30 днів.
- Рівні Information, Warning, Error.
- Номер рядка XLSX.
- Назва документа.
- File ID за необхідності для діагностики.
- Статус операції.
- Код HTTP-помилки.
- Діагностичні подробиці винятку.

Не записуй у журнали паролі, токени, секрети та інші конфіденційні облікові дані.

Виведення повідомлень у RichTextBox і запис у файл повинні працювати узгоджено, але помилка файлового логування не повинна аварійно завершувати додаток.

## 15. Розгортання

Налаштуй Release Publish для Windows x64:

- `SelfContained = true`
- `PublishSingleFile = true`
- `RuntimeIdentifier = win-x64`
- `IncludeNativeLibrariesForSelfExtract = true`
- `PublishTrimmed = false`
- `PublishAot = false`

Перевір сумісність залежностей із Single File.

Результат має розташовуватися у `dist/win-x64/` і містити самодостатній EXE, зовнішню конфігурацію та інструкцію користувача.

Не включай у дистрибутив реальні OAuth credentials, токени, логи, результати завантажень та тестові приватні файли.

- Для поширення застосунку слід враховувати політики OAuth Verification Google.
- Користувач повинен мати власний дозвіл на завантаження файлів.

Не обіцяй, що публічне розповсюдження із Restricted Scope завжди можливе без перевірки Google.

## 17. Вимоги до якості

- Жодних заглушок у головній функціональності.
- Жодних захардкоджених облікових даних.
- Жодних необроблених винятків, які закривають UI.
- Не використовувати застарілі Google API або застарілий OAuth OOB Flow.
- Не створювати власний сервер для авторизації.
- Не додавати непотрібних залежностей.
- Підтримувати nullable reference types.
- Дотримуватися сучасних рекомендацій .NET.
- Для складної логіки додавати лаконічні коментарі українською мовою.

Перед використанням Google SDK перевір фактичні сигнатури методів у встановленій версії NuGet-пакета. Не припускай, що старі приклади API залишилися незмінними.

Не зупиняйся після створення структури проєкту. Реалізуй усі компоненти MVP.

## 19. Критерії готовності

Застосунок вважається готовим, якщо:

- Компілюється без помилок.
- Має простий WinForms GUI.
- Приймає XLSX із назвами й Google Drive URL.
- Підтримує OAuth від імені користувача.
- Не вимагає Service Account.
- Завантажує доступні приватні файли.
- Перейменовує їх відповідно до Excel.
- Підтримує експорт Google Docs/Sheets/Slides.
- Не перезаписує випадково наявні файли.
- Продовжує роботу після помилки окремого документа.
- Відображає результати в журналі.
- Зберігає діагностику у файловому журналі.
- Коректно реагує на скасування.
- Виводить «Готово» після нормального завершення.
- Підтримує автономне розгортання.
- Не містить особистих ключів або токенів розробника.
- Має документацію для передавання іншому користувачу.

Після завершення надай короткий підсумок: які файли створені, які перевірки виконані, їх результати, як запустити застосунок та що залишається перевірити вручну з реальним Google-акаунтом.
