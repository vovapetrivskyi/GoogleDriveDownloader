# Перевірка секретів на етапі 10

Дата: 18.10.2026. Це локальна перевірка доступних матеріалів; вона не замінює перевірку майбутнього дистрибутива або незалежний аудит. Реальні Google credentials користувачем не надані, локальні auth-файли користувача не читались. Виробничі сервіси, залежності та lock-файли на цьому етапі не змінювались.

## Обсяг і результат

- Перевірено текстові файли з `git ls-files --cached --others --exclude-standard`: вихідний код, JSON, проєкти, документацію та правила Git. Пошук охоплював характерні формати Google API key, OAuth Client ID, Client Secret, access/refresh token і PEM private key. Виводилися лише лічильники/шляхи, без значень можливих секретів. Відомі навмисно синтетичні токени в unit-тестах відрізнялися від реальних кандидатів.
- Для трьох `samples/*.xlsx` переглянуто всі 29 XML/relationship entries: приватних ключів, характерних реальних Google credentials/токенів, externalLinks-пакетів або абсолютних шляхів профілю користувача не знайдено. Метадані авторства синтетичні; усі File ID/resource keys вигадані, що додатково перевіряють тести.
- Репозиторний `src/GoogleDriveDownloader/appsettings.json` та скопійований `bin/Debug/net10.0-windows/appsettings.json` прочитано як JSON: ClientId і ClientSecret порожні в обох.
- Власні зібрані `GoogleDriveDownloader.exe` і `GoogleDriveDownloader.dll` перевірено за тими самими ознаками у UTF-8/ASCII та UTF-16: збігів не знайдено. Це Debug build, а не Self-Contained Single File. Сторонні бібліотеки й увесь історичний Git не заявляються перевіреними цим пошуком.
- У повному інтеграційному тесті прочитано справжній JSONL і події LoggingService після завершення черги: повідомлення збігаються, п'ять успіхів мають контекст. Client ID/Secret, синтетичні access/refresh token, resource key та маркер сирого серверного тексту відсутні в перевірених виходах. LoggingServiceTests окремо перевіряє маскування повідомлення, контексту, вкладених винятків, Bearer і URL-параметрів. Тестові журнали створюються в тимчасових каталогах і прибираються.
- `git check-ignore --no-index` підтвердив виключення `.tools`, auth.dat, oauth-client.json, client_secret.json, logs, downloads і dist. Реальні файли credentials/токенів серед кандидатів у Git не знайдені. Синтетичні приклади не містять credentials і навмисно входять до репозиторію.

У межах цих перевірок секретів не виявлено. Пошук за форматами не може довести відсутність будь-якого можливого секрету; незнайомі формати чи приватний зміст документа він не класифікує.

## Поводження з локальними даними

`auth.dat` шифрується справжнім Windows DPAPI CurrentUser та прив'язаний до OAuth-конфігурації. Імпортований `oauth-client.json` містить Client ID/Secret у JSON і не є зашифрованим token store; він залишається в профілі власника й не призначений для поширення. Локальний вихід видаляє кеш, але не відкликає дозвіл у Google. Процедури ручного скидання та зміни акаунта наведено в README.

Журнал може містити номери рядків, назви документів і File ID — це передбачена SPEC діагностика, яка може бути приватною для користувача. Маскування токенів не робить увесь журнал публічним. UI та файл отримують уже очищені події; вихідні SDK-винятки Drive/OAuth не додаються до журналу цих операцій.

## Відкриті перевірки

Реальний Google-вхід, приватні документи, зовнішні журнали користувача, поведінка різних Windows-акаунтів і політики організації не перевірялися. Не завантажувались і не аналізувались сторонні приватні дані. Ручні сценарії перелічено в [TESTING.md](TESTING.md).

Каталог `dist/win-x64` ще не створено; перевірка фактичного складу постачання, publish-скрипт, Single File і запуск на чистій Windows належать до етапу 11. Перед передаванням треба перевірити саме отримані EXE, зовнішній appsettings із порожніми credentials та README; виключити auth-файли, логи, приватні XLSX, завантаження, кеші та тестові збірки.
