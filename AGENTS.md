# AGENTS.md

## Загальні правила
- Дотримуйся вимог `SPEC.md` — основного технічного завдання проєкту.
- Використовуй C# 14, .NET 10 та Windows Forms.
- Не змінюй затверджену архітектуру без технічного обґрунтування.
- Дотримуйся принципів SOLID, але уникай надмірного ускладнення архітектури.
- Не додавай функціональність, яка не передбачена `SPEC.md`, без необхідності.

## Організація роботи
- Використовуй `TASKS.md` як план реалізації та обліку прогресу.
- Виконуй лише етап, зазначений у поточному завданні.
- Не переходь до наступного етапу без окремого запиту користувача.
- Після завершення етапу оновлюй його статус у `TASKS.md`.
- Не переробляй уже реалізовані компоненти без необхідності.

## Якість коду
- Використовуй `async/await` для асинхронних операцій.
- Не блокуй UI-потік WinForms.
- Забезпечуй належну обробку винятків і скасування операцій.
- Не залишай заглушок, TODO або незавершеної основної функціональності в межах поточного етапу.
- Додавай коментарі українською мовою там, де логіка є нетривіальною.

## Безпека
- Не зберігай секрети, Access Token або Refresh Token у Git.
- Не записуй токени чи конфіденційні облікові дані в журнали.
- Використовуй OAuth 2.0 для доступу до приватних файлів Google Drive.
- Зберігай OAuth-токени захищено, відповідно до `SPEC.md`.
- Не додавай реальні облікові дані до тестів або вихідного коду.

## Перевірка результатів
- Після кожного етапу виконуй `dotnet restore` і `dotnet build`.
- Якщо є відповідні тести, виконуй `dotnet test`.
- Виправляй помилки компіляції та помилки тестів, спричинені поточними змінами.
- Не стверджуй, що збірка або тести успішні, якщо вони фактично не виконувалися.
- Якщо перевірка неможлива через обмеження середовища, чітко повідом про це.

## Завершення етапу
Після виконання кожного завдання:
1. Коротко опиши реалізовані зміни.
2. Переліч створені та змінені файли.
3. Повідом результати збірки й тестів.
4. Зазнач відомі проблеми або обмеження.
5. Онови `TASKS.md`.
6. Зупинись і не переходь до наступного етапу.
