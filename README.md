# Google Drive Downloader

Windows-застосунок для завантаження приватних файлів Google Drive за посиланнями з XLSX. Повні вимоги містяться в [SPEC.md](SPEC.md), послідовність реалізації та результати перевірок — у [TASKS.md](TASKS.md).

Реалізовано етапи 1–8: конфігурація, DI, журналювання, Google OAuth із DPAPI, читання XLSX, розбір URL, адаптер Drive, формування імен, безпечне збереження через .part та послідовна пакетна обробка з retry і статистикою. Головне вікно дозволяє імпортувати credentials, увійти, вийти, змінити акаунт і скасувати вхід. Підключення пакетного сервісу до повного інтерфейсу належить до етапу 9.

## Розробка

Потрібні Windows x64 та .NET SDK 10.0.402 або новіший patch тієї самої SDK feature band відповідно до `global.json`. Для роботи через IDE потрібна її версія з підтримкою .NET 10 і WinForms.

```powershell
dotnet restore GoogleDriveDownloader.sln --locked-mode
dotnet build GoogleDriveDownloader.sln --no-restore
dotnet test GoogleDriveDownloader.sln --no-build --no-restore
dotnet run --project src/GoogleDriveDownloader --no-build --no-restore
```

У поточному середовищі SDK завантажено локально в `.tools/dotnet`; системні SDK не змінено. Щоб використовувати його в поточному сеансі PowerShell:

```powershell
$env:DOTNET_ROOT = (Resolve-Path .tools/dotnet).Path
$env:DOTNET_ROOT_X64 = $env:DOTNET_ROOT
$env:PATH = "$env:DOTNET_ROOT;$env:PATH"
dotnet --version
```

Каталог `.tools` не входить до Git; після клонування потрібно встановити SDK окремо. Версії прямих залежностей зафіксовані в проєктах, транзитивних — у `packages.lock.json`. Після навмисної зміни залежностей слід виконати restore без `--locked-mode` та перевірити зміни lock-файлів.

## Структура

- `src/GoogleDriveDownloader` — єдиний виробничий WinForms-проєкт: `Presentation`, `Application`, `Infrastructure`.
- `tests/GoogleDriveDownloader.Tests` — 418 локальних перевірок конфігурації, DI, журналювання, OAuth/DPAPI, XLSX, URL, адаптера Drive, імен, файлового збереження та пакетної обробки. Google credentials і мережа для тестів не потрібні; DPAPI потребує завантаженого профілю поточного Windows-користувача.

## Вхідний XLSX і Google Drive URL

Читання на етапі 5 доступне через DI-сервіс `Application.Input.ExcelReader.ReadAsync(path, cancellationToken)`. Вибір XLSX у головному вікні буде підключено на етапі інтерфейсу. ExcelReader повертає `ExcelReadResult`: номер рядка заголовків і впорядковані `InputRow` з фізичним номером рядка, назвою, розібраним `DriveLink`, ознакою `IsValid` та списком помилок. Некоректний запис залишається в результаті, щоб його можна було врахувати й показати користувачу.

Підтримується лише `.xlsx`; читається перший аркуш незалежно від активної вкладки. Перший непорожній рядок повинен містити унікальні заголовки «Назва» та «Посилання» в довільному порядку й стовпцях. Регістр і пробіли навколо заголовків ігноруються. Преамбула перед заголовками не підтримується. Відсутні або дубльовані обов'язкові заголовки, порожній перший аркуш чи пошкоджена книга є помилкою книги.

| Назва | Посилання |
|---|---|
| Звіт за 2025 рік | `https://drive.google.com/file/d/FILE_ID_1/view` |
| Документ | `https://docs.google.com/document/d/FILE_ID_2/edit` |

Текстові значення обрізаються по краях. Порожні, заповнені лише пробілами та лише відформатовані рядки пропускаються. Непорожній рядок лише із зайвими стовпцями залишається помилковим записом: обов'язкові значення відсутні. Рядок із формулою або справжнім гіперпосиланням також вважається непорожнім.

Справжнє зовнішнє гіперпосилання має пріоритет над текстом комірки, навіть коли текст порожній або містить інший URL. Непридатний target або внутрішнє посилання стає помилкою рядка, без переходу до текстового URL. `HYPERLINK()` не виконується. Для формул читається лише збережений у XLSX результат: придатне значення використовується, відсутній/порожній результат чи Excel error стає помилкою рядка. Застарілі кешовані значення не перераховуються; за потреби оновіть книгу у власному Excel до імпорту. Вхідний файл відкривається лише для читання, не зберігається й не змінюється. ClosedXML працює у фоновому Task.Run; його синхронне початкове завантаження книги не приймає CancellationToken. Скасування перевіряється до та після нього і під час обходу рядків.

DriveLinkParser підтримує всі шість форм зі SPEC:

- `https://drive.google.com/file/d/{id}/view`
- `https://drive.google.com/open?id={id}`
- `https://drive.google.com/uc?id={id}`
- `https://docs.google.com/document/d/{id}/edit`
- `https://docs.google.com/spreadsheets/d/{id}/edit`
- `https://docs.google.com/presentation/d/{id}/edit`

Додатково підтримуються шлях `.../d/{id}` без кінцевої дії, кінцевий `/`, дії `view`, `edit`, `preview`, `copy` для тих самих типів шляхів, сторонні query-параметри та fragment на кшталт `#gid=0`. Відсоткове кодування декодується один раз; `resourcekey` зберігається окремо від File ID без зміни регістру. Параметри `id` і `resourcekey` розпізнаються без урахування регістру, дублікати відхиляються. File ID у шляху та query має збігатися, якщо присутні обидва.

Дозволені лише HTTPS та точні домени `drive.google.com` і `docs.google.com` зі стандартним портом. Сторонні домени, піддомени, облікові дані в URL, неоднозначні ID, недопустимі символи, шляхи з `..`, папки та непідтримувані типи URL відхиляються. Формат URL не визначає MIME файла й не підтверджує його існування або доступність: це перевіряє Drive-адаптер за метаданими Google API. Парсер не звертається до мережі та не переходить за посиланнями. Повідомлення помилок містять фізичний номер рядка, але не включають вихідний URL чи приватні фрагменти файла.

## Конфігурація

Зовнішній `appsettings.json` розташований поруч із EXE, копіюється при збірці та залишається зовнішнім при публікації. Програма читає його відносно `AppContext.BaseDirectory`, незалежно від робочої директорії. Зміни застосовуються після перезапуску.

| Налаштування | Значення за замовчуванням і допустимі значення |
|---|---|
| `GoogleOAuth:ClientId`, `ClientSecret` | Обидва порожні; це нормальний запуск без авторизації. Підтримується заповнення обох полів даними власного Desktop Client |
| `GoogleOAuth:Scope` | Лише `https://www.googleapis.com/auth/drive.readonly` |
| `Download:MaxConcurrentDownloads` | Лише `1` у MVP |
| `Download:RetryCount` | `3`, допустимо `0–3` повторів після початкової спроби |
| `Download:RequestTimeoutSeconds` | `100`, допустимо `1–3600` секунд на HTTP-запит |
| `Download:AuthorizationTimeoutSeconds` | `300`, допустимо `1–3600` секунд |
| `Download:DuplicatePolicy` | Лише `Rename`: суфікси без перезапису |
| `Export:DocsMimeType`, `SheetsMimeType`, `SlidesMimeType` | Лише MIME формату DOCX, XLSX, PPTX відповідно, наведені у файлі конфігурації |
| `Logging:MinimumLevel` | `Information`; також `Warning` або `Error`, без урахування регістру |
| `Logging:RetentionDays` | `30`, допустимо `1–3650` днів |

Для відсутніх окремих параметрів застосовуються наведені значення за замовчуванням. Некоректні загальні налаштування, відсутній або пошкоджений `appsettings.json` спричиняють зрозуміле повідомлення та коректне завершення запуску. Вміст JSON і значення секретів у повідомлення про помилку не включаються.

## Імпорт OAuth Desktop JSON і локальні токени

1. Натисніть «Імпортувати OAuth JSON» та оберіть стандартний файл Desktop Client, завантажений із Google Cloud Console.
2. Програма перевіряє секцію `installed`, обов'язкові credentials, Google endpoints і HTTP loopback redirect. Service Account, Web Client, неоднозначні або неповні файли відхиляються. Максимальний розмір файла — 1 МіБ.
3. Перевірена конфігурація зберігається у `%LOCALAPPDATA%\GoogleDriveDownloader\oauth-client.json`. Вхідний файл не змінюється; сторонні поля до локальної копії не переносяться.
4. Після успішного імпорту попередні токени видаляються; нові credentials застосовуються одразу. Для входу натисніть «Увійти через Google».

Імпортований клієнт має пріоритет над credentials із `appsettings.json`. Якщо імпортованого файла немає, використовується повна пара з `appsettings.json`. Неповна резервна пара не блокує коректний імпорт; без імпорту вона вважається неналаштованою. Пошкоджений або недоступний імпортований файл залишає програму неавторизованою та дозволяє повторити імпорт. Щоб повернутися до резервних credentials, видаліть локальний `oauth-client.json` і перезапустіть програму.

Захищене сховище `auth.dat` реалізує Google SDK `IDataStore`. Дані шифруються Windows DPAPI у режимі `CurrentUser` та прив'язуються до відбитка Client ID, Client Secret і scope. При зміні конфігурації, пошкодженні або неможливості розшифрування кеш не використовується; потрібна нова авторизація. Наявність credentials чи кеша сама по собі не підтверджує авторизацію.

Для запису `auth.dat` створюється зашифрований тимчасовий файл у тій самій директорії та виконується атомарна заміна. Відкриті токени на диск не записуються; незавершений тимчасовий файл видаляється. Розмір кеша обмежений 1 МіБ. При невдалому імпорті попередня конфігурація зберігається, але очищені перед записом токени можуть вимагати повторного входу.

Тести використовують синтетичні credentials і токени в тимчасових каталогах, перевіряють справжній DPAPI, збереження між запусками, відмови доступу й атомарного запису. Якщо середовище тестування не має завантаженого профілю Windows-користувача, DPAPI-тести не працюватимуть; не слід замінювати їх шифрування незахищеним сховищем.

## Вхід, вихід і зміна Google-акаунта

Після налаштування власного Desktop Client натисніть «Увійти через Google». Відкриється системний браузер із вибором акаунта та запитом лише `drive.readonly`. Використовуються GoogleWebAuthorizationBroker з `usePkce: true`, PKCE S256, offline access і SDK LocalServerCodeReceiver на `127.0.0.1` з випадковим портом. Відповідь додатково перевіряється за випадковим `state`; власного HTTP-сервера чи реалізації PKCE програма не містить.

Після дозволу поверніться до програми: статус зміниться на «Авторизовано», токени буде збережено у DPAPI-кеші. При наступному запуску придатний кеш відновлюється без браузера. SDK автоматично оновлює access token перед запитами. При `invalid_grant` сесія й непридатний кеш очищаються; повідомлення пропонує повторний вхід. Фонова операція не відкриває браузер. Натискання кнопки входу допускає одну інтерактивну спробу після невдалого відновлення, без нескінченних повторів.

«Вийти» завершує локальну сесію, очищає пам'ять сервісу та видаляє `auth.dat`. Ця дія не виходить із Google у браузері та не відкликає дозвіл у Google-акаунті. «Змінити акаунт» спочатку очищає поточну сесію, потім відкриває вибір акаунта й повторний запит дозволу. Після виходу, зміни клієнта чи акаунта застарілі сховища не можуть відновити кеш, а повторні HTTP-запити старої сесії не можуть перейти до нового акаунта.

«Скасувати вхід» перериває очікування браузера або мережі; також діє `Download:AuthorizationTimeoutSeconds`. HTTP-запити OAuth обмежені `Download:RequestTimeoutSeconds`. Відмова в дозволі, помилка мережі чи недоступний loopback-порт повертають безпечне повідомлення та дозволяють повторити дію. При закритті форми активна операція скасовується, і програма асинхронно чекає на очищення ресурсів. Якщо видалити `auth.dat` не вдалося, сесія в пам'яті завершується, але з'являється попередження: відновіть права доступу й повторіть зміну акаунта або видаліть файл при закритій програмі. До успішного очищення сервіс блокує повторне використання цього кеша в поточному процесі.

Для GoogleDriveService сервіс авторизації надає SDK `IConfigurableHttpClientInitializer`: додає Bearer, оновлює access token і допускає одне оновлення після HTTP 401. Повторний HTTP 401 очищає відхилену сесію навіть на останній дозволеній SDK-спробі. SDK debug-логування не підключається; вихідні OAuth-винятки, відповіді сервера та URL авторизації не передаються до журналу.

Ручна перевірка етапу 4 **не виконана**: реальні Google credentials відсутні, GUI вручну не запускався. Після підготовки власного Desktop Client:

1. Імпортуйте JSON, виконайте вхід у браузері, надайте доступ і перевірте статус та появу `auth.dat`.
2. Закрийте й повторно запустіть застосунок: сесія має відновитися без браузера.
3. Дочекайтеся закінчення access token і повторно запустіть застосунок: відновлення має оновити його без нового входу. Не редагуйте зашифрований кеш.
4. Натисніть «Змінити акаунт» і виберіть інший акаунт; потім «Вийти», перезапустіть програму та перевірте, що авторизація не відновилась.
5. Відкличте дозвіл у налаштуваннях Google-акаунта, дочекайтеся наступного оновлення токена й перевірте повідомлення про повторний вхід.
6. Окремо перевірте відмову в дозволі, кнопку скасування, закриття під час входу та тайм-аут. Переконайтеся, що можна розпочати новий вхід і що журнал не містить токенів чи credentials.

Автоматичні тести цих сценаріїв використовують справжній Google SDK, підмінену HTTP-взаємодію й receiver, синтетичні дані та справжній DPAPI. Вони не відкривають браузер, loopback listener або зовнішню мережу й не замінюють ручну Google-інтеграцію.
## Метадані, потокове завантаження й експорт Drive

Етап 6 надає DI-контракт `Application.Drive.IGoogleDriveService` та адаптер `Infrastructure.Drive.GoogleDriveService`. `GetMetadataAsync(link, cancellationToken)` повертає SDK-незалежні метадані: File ID, початкове ім'я, MIME, розширення, розмір, кошик і `canDownload`. `GetTransferFormat(metadata)` перевіряє можливість передачі та повертає MIME і розширення експорту. `DownloadAsync(link, metadata, destination, cancellationToken)` асинхронно передає вміст у наданий потік і повертає число записаних байтів лише після підтвердженого успіху.

Звичайні файли завантажуються через `files.get` із `alt=media` в оригінальному форматі. За MIME із метаданих Google Docs експортуються в DOCX, Sheets — XLSX, Slides — PPTX. MIME налаштовані в `Export`; тип файла не визначається за посиланням або його назвою. Папки, shortcuts та інші Workspace-типи відхиляються без передачі вмісту. Вміст не запитується для файла в кошику, `canDownload=false` або непідтвердженого дозволу. Поведінка відповідає [настанові Google щодо завантаження](https://developers.google.com/workspace/drive/api/guides/manage-downloads).

`supportsAllDrives=true` передається в підтримувані `files.get` для метаданих і вмісту. `files.export` не має такого параметра. Resource key передається окремо для кожного запиту в `X-Goog-Drive-Resource-Keys: fileId/resourceKey`, включно з media та export; він не додається до спільних заголовків чи query. [Документація Google про resource keys](https://developers.google.com/workspace/drive/api/guides/resource-keys) описує цей заголовок.

MediaDownloader використовує буфер близько 1 МіБ, повний файл у пам'ять не завантажується. Підтримується потік без Seek. Перед завершенням перевіряються `DownloadStatus.Completed`, `Exception`, кількість записаних байтів і відомий розмір звичайного файла. Помилка `exportSizeLimitExceeded` має окреме повідомлення про ліміт 10 МБ; додатково обмежено запис експорту до 10 × 1024 × 1024 байтів, навіть якщо відповідь HTTP формально успішна. Альтернативний `files.download` залишається майбутнім розширенням.

Потоком призначення володіє викликач: адаптер не закриває, не очищає, не перемотує його й не створює локальних файлів. Після помилки або скасування в потоці може залишитися частковий вміст. Створення/видалення `.part` і безпечне остаточне перейменування виконує FileStorageService; BatchDownloadService починає кожну повторну передачу з нового порожнього потоку. Успішна передача ще не означає, що викликач закрив або скинув на диск власний потік.

`DriveServiceException` повертає безпечне повідомлення, `Code`, `HttpStatusCode`, `IsTransient` і `RetryAfter` без сирого SDK-винятку, відповіді чи resource key. HTTP 404 означає «не знайдено або недоступний», без припущення про точну причину. Rate-limit 403/429 відрізняються від заборони доступу; тимчасові 500/502/503/504, мережеві помилки й тайм-аут позначено для пакетної retry-політики. Помилки запису цільового потоку та переповнення диска класифікуються окремо від мережевих. Підхід до HTTP-помилок звірено з [документацією Google](https://developers.google.com/workspace/drive/api/guides/handle-errors).

Внутрішній exponential backoff SDK вимкнено: сам адаптер не повторює 403/429/5xx і мережеві збої. OAuth допускає одне оновлення та повтор після HTTP 401. Заголовок Retry-After передається до пакетної політики повторів. `Download:RequestTimeoutSeconds` обмежує очікування заголовків і тіла відповіді; скасування користувача повертається як OperationCanceledException. HTTP-відповіді та SDK-клієнт звільняються, цільовий потік залишається відкритим.

Реальна Google-інтеграція етапу 6 **не виконана** через відсутність власних credentials. Автоматичні перевірки використовують фактичний SDK, синтетичні відповіді й потоки та підмінену HTTP-взаємодію. На етапі ручного приймання потрібно перевірити приватний звичайний файл, три Workspace-експорти, Shared Drive/resource key, заборону власника, недоступний файл, ліміт експорту та скасування з власним Google-акаунтом. GUI на цьому етапі вручну не запускався.

## Імена та локальне збереження

`Application.Storage.FileNameResolver.Resolve(requestedName, metadata, format)` формує назву зі стовпця «Назва». Для експорту розширення відповідає DOCX/XLSX/PPTX. Для звичайних файлів відомий MIME визначає розширення; допустимі `.jpeg`/`.tiff` з метаданих зберігаються. Для невідомого MIME використовуються `fileExtension` або розширення оригінального імені з метаданих; для text/plain без них — `.txt`, для інших невідомих типів без розширення воно не вигадується. URL не використовується.

Повтор правильного розширення прибирається, відомий неправильний суфікс замінюється. Незнайомі частини після крапки зберігаються як частина назви, оскільки їх призначення неможливо надійно визначити лише за текстом. Наприклад:

| Назва в XLSX | Фактичний формат | Результат |
|---|---|---|
| `Звіт.txt` | PDF | `Звіт.pdf` |
| `Звіт.PDF` або `Звіт.pdf.pdf` | PDF | `Звіт.pdf` |
| `Звіт.2025.final` | PDF | `Звіт.2025.final.pdf` |
| `backup.tar.gz` | gzip | `backup.tar.gz` |
| `CON` | PDF | `_CON.pdf` |

Недопустимі Windows-символи, керівні символи й некоректні UTF-16 surrogate замінюються на `_`; крайові пробіли/крапки прибираються, порожнє ім'я отримує основу «Документ». Зарезервовані назви, включно з COM/LPT та надрядковими цифрами, отримують префікс `_`. Шляхи з комірки перетворюються на одну назву, а файловий сервіс додатково відхиляє нерозібрані шляхи, device names і alternate data streams. Правила Windows звірено з [документацією Microsoft](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file).

Для сумісності з Windows Shell ім'я обмежене 255 одиницями UTF-16, повний звичайний шлях — 259. При збереженні основа додатково скорочується під вибрану директорію та суфікс дубліката; розширення й surrogate-пари не обрізаються. Надто довга директорія або розширення дають зрозумілу помилку з пропозицією скоротити шлях. Розширені device/long-path namespaces не приймаються. Існуюча директорія вибирається користувачем; сервіс не створює її самостійно.

DI-контракт `IFileStorageService.SaveAsync(directory, fileName, writeContent, context, cancellationToken)` приймає безпечну назву та асинхронний callback, який пише в потік. Повернення callback означає підтверджений успіх передачі; GoogleDriveService уже перетворює невдалий SDK progress на виняток. Файловий сервіс:

1. Створює у вибраній директорії унікальний `.gdd-{GUID}.part` через CreateNew, з асинхронним записом і FileShare.None.
2. Чекає на callback, перевіряє скасування, виконує FlushAsync і закриває потік.
3. Обирає вільне ім'я без урахування регістру, включно з колізіями з папками. Дублікати отримують ` (2)`, ` (3)` перед останнім розширенням.
4. Перейменовує файл у тій самій директорії через File.Move з overwrite=false. Якщо інший процес уже зайняв ім'я, обирає наступний суфікс. Після успішного Move повертає кінцевий повний шлях; це межа завершення операції.
5. При помилці або скасуванні видаляє лише власний `.part`. Якщо видалення не вдалося, журнал отримує Warning зі статусом PartialFileCleanupFailed і номером рядка; початкова помилка/скасування зберігаються. Невдалий `.part` потрібно видалити після відновлення доступу.

Кінцеве ім'я перевіряється як безпосередній файл вибраної директорії. Наявні файли не перезаписуються; резервні файли, журнали та інші `.part` не прибираються. I/O працює поза UI-потоком. Скасування перевіряється під час запису, переліку зайнятих імен і перед перейменуванням; після успішного Move результат залишається успіхом. FileStorageException розрізняє неправильну назву, довгий шлях, недоступну директорію, переповнення диска та інші I/O-помилки, не розкриваючи вихідні системні винятки.

Автоматичні тести використовують реальні тимчасові файли та підміняють лише граничні операції для відтворення race/cleanup/disk-full помилок без заповнення диска. Перевірено також інтеграцію з реальним Google SDK на підміненому HTTP: неповна або невдала передача не стає кінцевим файлом. Ручні перевірки GUI, Google та збоїв SMB/вимкнення живлення не виконувалися. Сервіс не відновлює файли після аварійного завершення процесу; такі `.part` можуть залишитися.

## Пакетна обробка

DI-сервіс `Application.Batch.BatchDownloadService` надає `RunAsync(workbookPath, directory, progress, cancellationToken)` та перевантаження для готового `ExcelReadResult`. Після авторизації викликач передає шлях до XLSX і наявну директорію. Робота виконується у фоні: перевірка рядка → метадані → формат і назва → новий `.part` → передача → безпечне перейменування → результат. У межах сервісу працює лише один пакет і одна передача одночасно; повторний одночасний запуск відхиляється. Після завершення, скасування чи помилки сервіс можна запускати знову.

`Download:RetryCount` задає 0–3 повтори після початкової спроби. Бюджет спільний для всього конвеєра рядка, максимум чотири спроби. Повторюються тимчасові мережеві збої, тайм-аути, неповна передача, rate-limit 403/429 та тимчасові 5xx, класифіковані адаптером. Затримки становлять 1/2/4 с плюс випадковий jitter від 0 до 1 с; якщо Retry-After більший, використовується він. Очікування можна перервати CancellationToken, включно з довгим Retry-After. Внутрішні transient-повтори SDK вимкнені. Кожна спроба заново отримує метадані; файловий сервіс прибирає невдалий `.part`, а наступна передача створює новий порожній файл, без дописування залишків.

Некоректні записи, 403 без rate-limit, 404, непідтримувані типи й перевищення ліміту експорту стають помилками окремих рядків; наступні рядки продовжують оброблятися. Втрата авторизації, переповнення диска, недоступність директорії/потоку, помилка локального збереження або непередбачений збій зупиняють пакет. Відомі помилки повертають безпечне повідомлення й код; невідомі винятки не розкривають системних подробиць або сирої відповіді Google.

`BatchDownloadResult` містить `Status` (`Completed`, `Cancelled`, `Failed`), `Results`, `Message`, `Total`, `Processed`, `Succeeded`, `Failed`, `Skipped`. Кожний вхідний запис має рівно один результат; повтори не збільшують лічильників. `Processed = Succeeded + Failed`, порожні рядки не входять до Total. Скасований поточний і ще не розпочаті рядки враховуються як Skipped; помилка, що спричинила критичну зупинку, враховується як Failed. На завершення `Processed + Skipped = Total`. Якщо читання XLSX перервано або не вдалося до отримання списку рядків, Total дорівнює нулю. Файл, уже успішно перейменований, залишається успішним за пізнього скасування.

`IProgress<DownloadProgress>` отримує початкові нулі, стан після кожного обробленого рядка та кінцеві лічильники з `CompletionStatus`. `CurrentRowNumber` позначає рядок проміжного результату. Для WinForms треба створити `Progress<DownloadProgress>` у UI-потоці. Журнал отримує результати рядків, події повторів і підсумок: «Готово» після нормального завершення навіть із помилками рядків, «Скасовано» після скасування або повідомлення про критичну зупинку. Налаштування повного GUI виконується на етапі 9.

Автоматично перевірено бюджети повторів, скасування під час метаданих, запису й затримок, очищення часткового вмісту, критичні зупинки, послідовність і статистику. Повний тест XLSX → справжній SDK із підміненим HTTP → файлове збереження включає rate-limit, неповний вміст, недоступний запис, неправильний URL, DOCX-експорт і дублікат імені. Реальні Google-запити та ручна робота GUI не перевірялися.

## Журналювання

Логи Serilog зберігаються у `%LOCALAPPDATA%\GoogleDriveDownloader\logs\log-yyyyMMdd.jsonl`. Кожний рядок — JSON-подія з часом, рівнем, повідомленням, номером рядка XLSX, назвою документа, File ID, статусом, HTTP-кодом і очищеною діагностикою винятку, якщо вони надані. Ротація щоденна; старі файли прибираються за віком під час відкриття чергового журналу.

Запис відбувається у фоновому потоці. Відомі OAuth credentials, включно з новими імпортованими значеннями, іменовані токени, паролі й Bearer-значення маскуються перед передаванням як у Serilog, так і в події `ILoggingService.EntryLogged`. UI-підписники мають використовувати `IProgress<LogEntry>`, створений у UI-потоці. Фільтр мінімального рівня діє для обох виходів.

Якщо файл недоступний або запис неповний, програма показує попередження й припиняє файлове журналювання до перезапуску; підписники продовжують отримувати події. Це службове попередження надходить незалежно від мінімального рівня. При звичайному закритті DI-контейнер асинхронно завершує чергу та звільняє файл.

Не додавайте до Git OAuth credentials, токени, приватні документи або конфігурацію з реальними секретами. Імпортований OAuth JSON, токени, журнали, тимчасові файли та артефакти виключені через `.gitignore`; у репозиторному `appsettings.json` credentials повинні залишатися порожніми.
